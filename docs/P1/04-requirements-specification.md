## 1 引言
### 1.1 目的
本文档基于AI生成的需求初稿，结合真实校园用户调研数据和学生项目开发能力，明确平台的功能边界与实现标准。剔除AI捏造的商业级高复杂度功能，补充AI遗漏的校园核心刚需，为4人团队10周内的开发、测试、验收提供统一依据。

本文档面向项目全体开发人员、测试人员、指导教师及评审人员。

### 1.2 范围
- **产品名称**：校园互助服务平台(CampusHub)
- **目标用户**：南京大学在校学生（需求方/服务方）、平台学生管理员
- **核心交付**：完整可用的MVP版本，覆盖85%用户高频刚需
- **包含范围**：基础用户管理、多类型互助需求发布、订单全流程、订单内简易交流、评价信用、基础审核与后台
- **明确剔除**：复杂数据可视化、自动化内容审核、个性化推荐算法、在线支付、完整即时通讯、校园地图定位

## 2 总体描述
### 2.1 产品前景
本产品是面向大学校园的轻量互助信息撮合平台，通过"发布需求—任务撮合—沟通执行—结果评价"的闭环流程，解决当前校园互助信息碎片化、匹配效率低、缺乏信任机制的痛点。平台聚焦**高频刚需场景**，强调轻量、便捷和校园专属可信性，不追求商业级功能复杂度。

### 2.2 产品功能概述
系统主要包含以下功能模块：
1. **用户管理模块**：注册、登录、校园邮箱认证、个人资料维护
2. **需求发布模块**：支持8类互助需求发布，含分类差异化字段
3. **任务大厅模块**：需求浏览、筛选、搜索、详情查看
4. **订单管理模块**：接单、确认、状态流转、历史记录查询
5. **消息通知模块**：系统通知、订单内简易留言
6. **评价与信用模块**：订单完成后互评、信用分计算与展示
7. **举报与审核模块**：用户举报、管理员人工审核处理
8. **基础后台模块**：用户管理、需求管理、举报处理、基础运行概览

根据用户调研结果，平台优先支持**咨询问答、跑腿代取、二手交易、失物招领**四类高频核心场景。

### 2.3 用户特征
#### 2.3.1 学生用户
- 主要群体：南京大学在校本科生、研究生
- 技术能力：熟悉移动互联网产品，操作能力强
- 使用习惯：碎片化使用，追求快速发布、快速响应
- 核心诉求：交易安全可信、操作简单、匹配效率高
- 同一用户可同时担任需求方和服务方

#### 2.3.2 平台管理员
- 身份：以项目团队成员担任管理员为主，学生志愿者仅作为后续可选辅助角色
- 核心职责：内容审核、举报处理、基础平台维护
- 能力要求：无需专业运维能力，能快速处理常见问题

### 2.4 运行环境
#### 2.4.1 客户端环境
- Web浏览器：Chrome、Edge、Firefox、Safari等主流现代浏览器
- 适配：优先桌面端，兼容移动端H5页面
- 推荐分辨率：1920×1080（桌面端）、375×667（移动端）

#### 2.4.2 服务器环境
- 操作系统：Linux（Ubuntu 20.04+）
- Web服务器：Nginx
- 应用服务器：Spring Boot（后端）、Vue.js（前端）
- 数据库：MySQL 8.0
- 对象存储：免费云存储服务（用于图片上传）

### 2.5 设计与实现约束
1. **时间约束**：10周开发周期，2026年6月21日前完成MVP交付
2. **人力约束**：3人学生团队，人均每周投入约6小时
3. **成本约束**：使用免费云服务器和开源工具，无额外预算
4. **技术约束**：采用前后端分离架构，技术栈统一为Spring Boot+Vue.js
5. **能力约束**：不实现需要专业运维、复杂算法或第三方付费服务的功能
6. **合规约束**：遵守学校网络安全规定，保护用户个人隐私
7. **收费策略约束**：MVP阶段基础功能免费，不实现在线支付与平台抽成；涉及报酬的任务由用户线下协商完成，平台仅提供信息撮合与流程管理

### 2.6 假设与依赖
1. 用户拥有有效的南京大学学校邮箱
2. 用户可通过互联网访问平台
3. 学校允许学生使用此类平台开展校园互助活动
4. 免费云服务器可支持至少200名同时在线用户
5. 依赖GitHub进行代码管理和CI/CD流水线搭建

### 3.2 核心用例概述
#### 3.2.1 学生发布快递代取需求
- 前置条件：用户已登录并完成身份认证
- 基本流程：选择"快递代取"类别→填写快递信息和报酬→提交发布→等待接单
- 后置条件：任务进入待接单状态，展示在任务大厅

#### 3.2.2 学生接单完成任务
- 前置条件：用户已认证且无接单限制
- 基本流程：浏览任务大厅→查看需求详情→点击接单→等待发布者确认→完成服务→上传凭证→等待确认
- 后置条件：订单状态变为已完成，进入评价流程

#### 3.2.3 学生发布失物招领信息
- 前置条件：用户已登录并完成身份认证
- 基本流程：选择"失物招领"类别→填写物品信息和丢失/拾获地点→提交发布
- 后置条件：失物招领信息展示在任务大厅

#### 3.2.4 学生发布咨询问答需求
- 前置条件：用户已登录并完成身份认证
- 基本流程：选择"咨询问答"类别→填写问题内容、期望回答方式和截止时间→提交发布→等待他人回答或接单
- 后置条件：咨询需求展示在任务大厅，可进入交流和反馈流程

#### 3.2.5 管理员处理举报
- 前置条件：管理员已登录后台
- 基本流程：查看举报列表→打开举报详情→核实内容→做出处理决定→通知举报人
- 后置条件：举报单状态更新，违规内容/用户被处理

### 3.3 业务规则
1. 未认证用户仅可浏览公开需求，不可进行发布、接单和消息发送操作
2. 每个需求必须属于一个明确的分类
3. 单人需求在被确认接单后，其他用户不可再接单
4. 只有已完成的订单才能进行评价
5. 已取消、已关闭的需求不可再次接单
6. 被封禁用户不得发布需求、接单和发送消息
7. 平台禁止发布违法、诈骗、色情、侮辱等违规内容
8. 交易类需求必须注明价格或"面议"
9. 组队类需求必须注明人数要求和活动时间
10. 取件码等敏感信息仅在订单确认后对接单者可见
11. 平台支持需求发布者选择“定价 / 面议 / 积分”中的结算方式；选择“定价”时必须填写大于 0 的金额，并选择微信、支付宝或现金。二手交易中金额表示售价、支付方式表示收款方式，其他需求中金额表示酬金、支付方式表示付款方式；MVP 阶段仅记录结算约定，不提供平台内支付或积分结算功能
