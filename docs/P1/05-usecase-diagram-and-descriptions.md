## 2. 核心用例详细描述（3个）

### 用例 UC-02：发布需求

| 项目 | 内容                                                                                                                                                                                                                                                                         |
|------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **用例名称** | 发布需求                                                                                                                                                                                                                                                                       |
| **参与者** | 已认证学生                                                                                                                                                                                                                                                                      |
| **前置条件** | 1.用户已成功注册并登录。 2.用户已完成校园身份认证。3. 用户账号未被禁用、禁言或限制发布。                                                                                                                                                                                                                           |
| **后置条件** | 1.一条新需求被成功创建。2.该需求进入“待接单”或“待审核”状态。3.该需求可出现在任务大厅或管理员审核列表中。                                                                                                                                                                                                                  |
| **基本流** | 1.用户进入“发布需求”页面。2.用户选择需求类别，例如快递代取、学习辅导、二手交易、组队匹配、失物招领或咨询/问答。3.系统展示该类别对应的表单字段。4.用户填写标题、描述、地点、截止时间、报酬/预算、联系方式等必要信息，并可上传图片。5. 用户提交发布请求。6. 系统校验字段完整性、格式合法性以及时间和价格等业务规则。7. 系统执行敏感词和违规内容检测。8. 校验通过后，系统保存该需求。 9. 系统根据分类和规则将需求置为“待接单”或“待审核”状态。10. 系统向用户返回“发布成功”提示。                                  |
| **替代流** | A1：信息填写不完整或格式不合法 1.系统校验失败。2.系统提示具体错误信息，例如标题为空、时间非法、价格格式错误。3.用户修改后重新提交。A2：上传图片失败 1.系统提示上传失败。2.已填写的文本内容保留。3.用户可重新上传后再次提交。A3：内容命中敏感词或违规检测 1.系统拒绝直接发布，提示内容需修改，或转入“待审核”状态。2.用户可修改后重新提交，或等待管理员审核。A4：用户未认证 1.用户尝试发布需求。2.系统提示需先完成校园身份认证。3.系统引导用户进入认证流程。 |

### 用例 UC-04：接单

| 项目 | 内容                                                                                                                                                                                                                                                                                                                             |
|------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **用例名称** | 接单并完成任务                                                                                                                                                                                                                                                                                                                        |
| **参与者** | 已认证学生（接单者）已认证学生（发布者）                                                                                                                                                                                                                                                                                                           |
| **前置条件** | 1. 发布者已发布有效任务。2. 接单者已登录并完成身份认证。3. 接单者未被限制接单，信用状态允许参与任务。4. 任务当前状态允许被接单或报名。                                                                                                                                                                                                                                                      |
| **后置条件** | 1.成功情况下，订单状态为“已完成”，双方可互评。2.异常情况下，订单可能为“已取消”“已关闭”或“已超时”。3. 系统保留完整订单历史记录。                                                                                                                                                                                                                                                                     |
| **基本流** | 1.接单者进入任务大厅浏览任务。2.接单者通过筛选、搜索或查看详情找到目标任务。3接单者点击“接单”或“报名”。4.系统检查任务状态、人数限制以及接单者资格。5.若校验通过，系统记录接单信息，并为双方建立订单记录。6.系统将订单状态更新为“待确认”或“进行中”。7.发布者与接单者通过站内聊天沟通任务细节、时间地点等信息。8.接单者执行任务。9.接单者提交完成结果。10.发布者确认任务完成。11.系统将订单状态更新为“已完成”。12.系统开放双方互评入口。                                                                                          |
| **替代流** | B1：任务已被他人接走1.接单者点击接单。2.系统发现该任务已被接单或已关闭。3.系统提示“任务已被接走”或“当前不可接单”。B2：接单者信用过低或账号受限1.系统检查接单者资格失败。2.系统拒绝接单，并提示原因。B3：任务类型为需筛选报名1.接单者提交报名申请。2.发布者查看报名信息。3.发布者确认其中一名或多名合适人选。4.系统再生成正式订单。B4：任务执行后发生争议1.接单者提交完成结果。2.发布者不确认完成，或提出异议。3.系统允许双方补充聊天记录、说明或凭证。4.用户可发起举报或申诉，由管理员介入处理。B5：订单超时未处理1.订单在规定时间内未被确认。2.系统自动提醒双方。3.如仍未处理，系统可自动关闭订单或标记超时。 |

### 用例 UC-07：评价订单

| 项目 | 内容                                                                                                                                                                                                                                                              |
|------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **用例名称** | 管理员处理举报                                                                                                                                                                                                                                                         |
| **参与者** | 管理员、举报用户、被举报用户                                                                                                                                                                                                                                                  |
| **前置条件** | 1. 举报用户已提交有效举报。2. 管理员已登录后台系统。3. 举报内容包含基本类型、描述和必要证据。                                                                                                                                                                                                             |
| **后置条件** | 1.举报单状态被更新为已处理、已驳回或待补证。2.平台记录处理结果及管理员操作日志。3.举报人收到通知；必要时被举报人也收到通知。                                                                                                                                                                                               |
| **基本流** | 1.管理员进入后台举报管理页面。2.管理员查看举报列表。3.管理员打开某条举报详情。4.系统展示举报对象、举报类型、举报说明、证据材料、关联任务或聊天记录。5.管理员核实证据并判断举报是否成立。6.若举报成立，管理员执行相应处理措施，如下架需求、警告用户、禁言、封号、信用扣分等。7.系统记录管理员处理结果和操作日志。8.系统将处理结果通知举报用户。9.若被举报用户有申诉权，系统允许其发起申诉。                                                          |
| **替代流** | C1：举报证据不足1.管理员查看举报详情后发现证据不足。2.管理员驳回举报，或要求补充材料。3.系统通知举报用户处理结果。C2：举报成立但情节轻微1.管理员确认举报有效。2.管理员对被举报用户进行警告或轻度处罚。3.系统记录处罚结果。C3：举报成立且情节严重1.管理员确认存在严重违规。2.管理员执行下架内容、禁言、封号、信用扣分等处罚。3.系统限制被举报用户继续发布、接单或发送消息。C4：被举报用户提出申诉1.被举报用户收到处罚结果后发起申诉。2.系统将申诉提交给管理员。3.管理员重新审查并更新处理结果。 |
