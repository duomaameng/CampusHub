## 第一条：AI 使用原则
1. AI 是辅助工具，不替代团队成员的工程责任。
2. 所有 AI 生成内容必须经过人工审查、修改和确认后，才能进入项目仓库。
3. 团队成员对自己提交的代码、文档和设计负责。

## 第二条：AI 使用范围
### 2.1 允许使用 AI 的场景
- 需求文档初稿生成
- README 初稿整理
- 代码模板，部分代码生成。

### 2.2 禁止直接使用 AI 输出、必须额外审查的场景
- 核心业务逻辑代码
- 数据库表结构设计
- 安全相关实现
- 页面设计

### 2.3 完全禁止使用 AI 的场景
- 个人总结/反思直接代写并原样提交
- 未经理解直接复制 AI 代码提交

## 第三条：过程记录要求
1. 所有与 AI 的关键交互 Prompt 必须保存记录。
2. Git commit message 必须标注 [AI-assisted] 或 [Human-written]。
3. 每阶段完成后填写 AI 协作反思日志。

## 第四条：代码合入规则
1. AI 生成代码必须至少经过 1 名团队成员 Code Review。
2. 每位成员在每个编码阶段至少完成 2 个完全手写的核心函数。
3. 未通过编译检查、风格检查、人工审查的内容不得合入主分支。
4. 所有合入通过 Pull Request 进行，不允许直接提交到 main。

## 第五条：违约处理
1. 首次违反：团队内提醒并要求补充审查或补充记录。
2. 再次违反：在阶段总结中记录，并由该成员补充手写内容或测试说明。
3. 严重违反：取消该部分成果的团队内部认定，并重新完成对应任务。
